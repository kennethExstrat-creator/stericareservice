# AI in the SteriCare inspection app

How the app hands inspections to AI models (BUILD_SPEC section 9), how to connect a model, and the contract for anyone building a service on the other end. Code: `lib/ai/` (server only) and `lib/schemas/`.

## What AI does here

| Hand-off | What happens | Output |
|---|---|---|
| **AI report** (9.1) | The admin sends a submitted or approved inspection. The app POSTs the export JSON to a report service. | The URL of the finished client report, stored in `inspections.report_url`. |
| **AI second opinion** (9.2) | An AI reviews the app's computed results, the inspector's data, comments and remark, and some photos. | A review: suggested result, confidence, summary, findings with evidence, questions for the inspector. |
| **Steri-AI Summary** | The inspector taps Steri-AI Summary on the Conclusion, and Claude drafts the Inspection Summary from the inspection in SteriCare's house style (below). Text only: it never changes a result. | A draft for the field, which the inspector checks, edits and signs as their own text. |

The app does not lay out reports and does not decide results. The report and the second opinion start from one document: the inspection export, validated by `ExportSchema` (`lib/schemas/export.ts`).

## Guardrails

- **Never automatic.** The AI never changes an inspection, a module result or the final result. Its review is stored next to the inspection and shown beside it.
- **The admin decides.** For each finding the admin records agree, disagree (a note is required) or fixed (`AiReviewActionSchema`).
- **Evidence or a question.** The reviewer must cite the values, box/carton numbers and photo ids behind every finding, and ask the inspector instead of guessing when evidence is missing. A review that names a module or photo the inspection does not have is rejected, from any provider.
- **Inspection text is data.** Comments, remarks and captions are passed as data; the reviewer is told never to follow instructions found in them.
- **Not connected is a normal state.** With nothing configured the review panel shows "AI Second Opinion Not Connected" and the report button shows "AI Not Connected" with a JSON download.

## Choosing a provider

Set these in `.env.local` (Vercel: Project Settings > Environment Variables). Empty values count as unset. Configuration is read on every request, so a bad value turns that hand-off "misconfigured" instead of crashing the app. The status names the variable to fix and what it accepts, but never repeats the value, so a key or a URL with a token pasted on the wrong line does not reach the screen.

| Variable | Default | Purpose |
|---|---|---|
| `AI_REVIEW_PROVIDER` | `auto` | `auto`, `webhook`, `claude`, `mock` or `off`. |
| `AI_REVIEW_WEBHOOK_URL` | | Second-opinion service. |
| `AI_REPORT_WEBHOOK_URL` | | Report service. |
| `AI_WEBHOOK_SECRET` | | Signs both webhooks. At least 16 characters: `openssl rand -hex 32`. |
| `ANTHROPIC_API_KEY` | | Runs the second opinion directly on Claude. Server only. |
| `AI_REVIEW_MODEL` | `claude-opus-5-5` | Claude model for the second opinion: a Claude API model id, starting with `claude-`. |
| `AI_REVIEW_EFFORT` | `high` | `low`, `medium`, `high`, `xhigh` or `max`. `xhigh` and `max` get 64,000 output tokens and up to 30 minutes per review. |
| `AI_REVIEW_MAX_PHOTOS` | `6` | Photos attached to a Claude review, 0 to 20. |
| `AI_SUMMARY_MODEL` | `claude-sonnet-5-5` | Claude model for the Steri-AI Summary on the Conclusion: a Claude API model id, starting with `claude-`. The model saved in Steri-AI Settings wins. |
| `ENABLE_MOCK_AI` | | `true` allows the mock reviewer and mock receivers in a production build (for a preview deployment). |

How the second opinion resolves:

| `AI_REVIEW_PROVIDER` | Result |
|---|---|
| `auto` (or unset) | The webhook if `AI_REVIEW_WEBHOOK_URL` is set, else Claude if `ANTHROPIC_API_KEY` is set, else not connected. |
| `webhook` | The webhook; misconfigured without `AI_REVIEW_WEBHOOK_URL`. |
| `claude` | Claude; misconfigured without `ANTHROPIC_API_KEY`. |
| `mock` | The deterministic mock reviewer (test data). Blocked in production unless `ENABLE_MOCK_AI=true`. |
| `off` | Not connected, whatever else is set. |

The report is a webhook only: connected when `AI_REPORT_WEBHOOK_URL` is set. Webhook URLs must be `https://` in production (`http://localhost` is allowed) and must not contain a user name or password.

Server code calls `requestAiReview(exportDoc)` and `requestAiReport(exportDoc)` from `@/lib/ai`. Neither throws: they return `{ ok: true, ... }` or `{ ok: false, reason, message }`, where the message is safe to show an admin. `getAiStatus()` returns what the UI may show (labels, provider, model) with no URLs, keys or secrets.

| `reason` | Meaning |
|---|---|
| `not_connected` | Nothing configured for this hand-off. |
| `misconfigured` | A variable is invalid, or Claude rejected the API key or model. The message names the variable. |
| `refused` | Claude declined, and no fallback model completed the review. |
| `invalid_response` | The answer was not valid JSON in the expected shape, was cut off or broke off, or named modules or photos that are not in the inspection. |
| `timeout` | No complete answer within the time limit. |
| `error` | HTTP or network error, rate limit, outage, or an export that failed validation. |

## AI Settings

Admin > Steri-AI Settings (`/admin/ai`, `app/(app)/admin/ai/`; Kenneth, 12 October 2026: "separate into general, AI cost and inspection AI setting, switching by toggle") holds the Anthropic API key, the Claude model for each job and the second opinion's effort and photos, so they can be changed without touching the server's variables, and shows what Steri-AI costs. A pill switch under the title picks one of three views, each its own address, so a reload, a bookmark or Back opens the same one (`_components/view-state.ts`): General (`/admin/ai`), Inspection Settings (`?view=inspection`) and Steri-AI Cost (`?view=cost`, with `&period=7|30|90|all` and `&currency=myr|usd`; unknown values fall back to the defaults, the last 30 days in ringgit; the currency is always written, so a link shows what its sender saw). Each view loads only its own data and saves only its own settings, through its own Server Action (`actions.ts`: an active admin only, checked with zod):

- **General**: the API key, write-only (`saveApiKeyAction`, `removeAiKeyAction`). It is encrypted before it is stored (`ai_settings`, migration `20261009120000`; AES-256-GCM keyed from `SUPABASE_SECRET_KEY`, `lib/ai/secret-box.ts`), and the screen only ever shows its last four characters. An Admin API key (`sk-ant-admin…`) is refused: it cannot call Claude. Rotating the Supabase secret key makes a saved key unreadable: the screen says so and asks for it again. Remove Saved Key goes back to `ANTHROPIC_API_KEY`, if set. **Test Connection** (`testAiConnectionAction`) asks Anthropic whether the typed key, else the key in use, may use the models in use (`GET /v1/models/{id}`, no tokens billed, nothing recorded).
- **Inspection Settings** (`saveInspectionSettingsAction`): Reading Documents' model (New Inspection, Source Documents and Auto-Sort; default `claude-opus-5-5`) and Second Opinion's model (default `claude-opus-5-5`), from a list of current Claude models or any other Claude model id; the second opinion's **Effort** (Low, Medium, High) and **Photos per Review** (0 to 20), the two settings that most change what a review costs. A model the price list has no price for says so, with a link to Steri-AI Cost. When `AI_REVIEW_PROVIDER` sends reviews to the webhook or the mock reviewer, or switches them off, one line under Second Opinion says these are not used. A third card, **Inspection Summary**, with its own Save (`summary-actions.ts`: `saveSummarySettingsAction`, and `previewSummaryAction` for Try It), holds the Steri-AI Summary's model and house style ("Steri-AI Summary" below). The shortforms moved to Admin > Defects > Shortforms (below).
- **Steri-AI Cost**: below.

The saved values lie over the variables (`loadAiEnv` in `lib/ai/settings.ts`): a saved key wins over `ANTHROPIC_API_KEY`, the saved models over `AI_REVIEW_MODEL` and `AI_DOCUMENT_MODEL` (and the summary's, `ai_settings.summary_model`, over `AI_SUMMARY_MODEL`: `loadSummarySetup`), and the saved effort and photos (`ai_settings.review_effort` and `review_max_photos`, migration `20261013120000`) over `AI_REVIEW_EFFORT` and `AI_REVIEW_MAX_PHOTOS`. The status cards, the review panel and the second opinion all read through it. `xhigh`, `max` and the provider stay variables: while `AI_REVIEW_EFFORT` is `xhigh` or `max` and no effort is saved, the picker shows it as Extra High (Server Setting) or Max (Server Setting), and saving keeps it.

## Reading order documents

On `/inspections/new` the **Source Documents** card is the capture screen's first step on the form, with its title, Files / Media switch and rows (`source-documents-panel.tsx` and `use-held-sources.ts` in `app/(app)/inspections/new/_components/`, the rules in `_lib/sources.ts`), so every paper and photo can come in while the inspection is created (Kenneth, 12 October 2026). Nothing is stored before Create, since there is no inspection yet: the files stay in the browser, and Cancel or leaving the page drops them.

- **Files**: PDFs and photos of the PO, packing list, inspection request or inspection form, and Excel (`.xlsx`, `.xls`) or CSV files (Kenneth, 26 October 2026; "Excel and CSV files" under Source Documents), several at once (photos are made 2048 px JPEG in the browser, `lib/photos/readable.ts`, as on the capture screen; a spreadsheet is typed as one, Windows typing a CSV as Excel; up to the file bucket's 50 MB). Each is a row: the name, what Steri-AI did with it beside it (Waiting for Steri-AI, Steri-AI is reading, **Steri-AI Read**, **Not Read** with the reason and Read Again, or Read after Create), then Preview (the file in a dialog on the page; a spreadsheet's sheets as tables, read on the server from the file held here, up to 4 MB: `POST /api/sheets`) and Remove.
- Steri-AI reads them **one at a time, only while the form still lacks its client, manufacturer, product type or product name** (the product name only where the template's header has one). The Server Action `readDocument` (`app/(app)/inspections/new/actions.ts`) sends the file to Claude (`lib/ai/document-reader.ts`) with the client and manufacturer lists the user can pick from; Claude reads the file itself (no separate OCR) and answers in a JSON schema (`DocumentReadingSchema`, `lib/schemas/document-fill.ts`), at low effort so the inspector waits seconds, not minutes. A file over 4 MB (a request's limit) or of a type the reader does not take is not read here. Files not read here are read after Create, on Source Documents.
- `checkReading` (`lib/inspections/document-fill.ts`) keeps only ids from the lists, real dates and known sizes, and adds up the lines of one size.
- A reading fills the client, manufacturer, product type and product name **only where nothing is chosen or typed yet: the first answer wins** (`formFill`). A company that is not in the lists is named so an admin can add it. Under the files the card lists, short, what it filled and what goes in with Create; Claude's note on anything unclear is the file's badge's tooltip.
- The PO, product code, factory glove code, inspection, manufacturing and expiry dates, and per size the cases and lot numbers, of every file read are merged, the first answer winning field by field and size by size (`mergeFills`), and go in with Create (`documentFill`, `applyDocumentFill`): only fields the template shows, only sizes it offers, never over a value already set (for example by Start From Previous).
- **Media**: the visit's photos and videos (videos up to 50 MB), as rows with a thumbnail, Preview and Remove, under a drop area like Auto-Sort's. Auto-Sort files them once the inspection exists.
- **On Create** `createInspection` answers the new inspection's id instead of redirecting; the form then hands every file over for it, in the background: the documents to the page's upload queue as Source Documents (`module_key` `source_documents`), the photos and videos to an Auto-Sort run (`autoSort`, below). The queue and the run belong to the page, not to the screen, so they carry on while the form opens the inspection on Source Documents: there the uploads show, each document is read in full (one read on the form too, which only took the order details), and Media shows the sort's progress. No file is posted with the form, so a Server Action's 5 MB limit never applies to them. The audit log records `filled_from_document` with the names of the files read, the fields filled and who uploaded them.
- Everything stays editable: the AI suggests, the inspector checks.


## Source Documents

The first step of every inspection, before its modules (`SOURCE_DOCUMENTS_KEY`, `lib/inspections/source-documents.ts`; the capture screen opens on it unless `?module=` names another page). The inspector uploads every file about the inspection: the handwritten inspection form, the PO, packing lists, lab reports, photos of labels and cartons. They are `inspection_files` rows with `module_key` `source_documents`, uploaded through the page's queue like any file; photos are made 2048 px JPEG first. Files added on New Inspection arrive here the same way after Create, and are read in full like any other (New Inspection only took the order details from them).

- Each uploaded file is read once, one at a time (`use-source-documents.ts`, Server Action `readSourceFile` in `app/(app)/inspections/[id]/source-actions.ts`, `lib/ai/source-reader.ts`). Claude gets the file, the inspection's included modules with each module's data JSON Schema, settings and sizes (cached for the next file), and the data entered so far, and answers values for the empty fields it can read, as JSON (no structured output: per-size records do not fit a strict schema).
- **Excel and CSV files** (Kenneth, 26 October 2026: "make the source document to support excel and csv file reading"): Files takes `.xlsx`, `.xls` and `.csv` besides PDFs and photos, stored as they are with their own type (migration `20261026140000`). The bytes decide what a file is (`sniffSpreadsheet`, `lib/photos/sniff.ts`): an `.xlsx` is a zip holding Excel's `[Content_Types].xml` and `xl/workbook.xml` (a Word file renamed `.xlsx` is refused), an `.xls` an OLE2 file named or typed as Excel, a CSV text named `.csv` or typed as one, whatever type the browser gives it (Windows types it as Excel, others text/csv, text/plain or nothing). Claude takes no spreadsheet, so Steri-AI gets its text, as a plain-text document titled with the file's name (`lib/ai/document-file.ts`, both readers; `lib/spreadsheets/read.ts`, with SheetJS, on the server only): a CSV as it is (UTF-8 without its byte order mark, else windows-1252, UTF-16 by its mark); a workbook sheet by sheet, each as CSV under a line `Sheet: <name>` ("(hidden)" after a hidden sheet's name), empty sheets and rows left out, the values as Excel shows them: formula results, never the formulas, formatted numbers, and a date in the computer's short date format (which each computer shows its own way) as YYYY-MM-DD. At most about 300,000 characters (some 75,000 tokens; `MAX_SPREADSHEET_TEXT`), cut at the end of a row with a last line `[truncated: N more rows]`. Both readers' prompts say how a spreadsheet comes (`SPREADSHEET_NOTE`, one sentence; the system prompt stays the same for every file), and the same fill rules apply as to a PDF. Up to 10 MB (`MAX_SPREADSHEET_BYTES`, as a PDF up to 20 MB): a larger one, a password-protected one, or one that cannot be opened or holds nothing is **Not Read**, with why. Preview shows each sheet as a table, Excel's column letters and row numbers kept in view, a tab per sheet when there are several (hidden ones marked), at most 200 rows and 30 columns of it with a line saying what was left out; it is read on the server through the user's own session (`GET /api/inspections/[id]/files/[fileId]/sheets`, `lib/spreadsheets/sheets.ts`: `lib/auth` checks the caller, Row Level Security decides the file), from a Route Handler rather than a Server Action, since Next.js runs a page's Server Actions one at a time and the preview would wait behind a reading. The row has a spreadsheet's icon. Dropped on Media or Auto-Sort, a spreadsheet is refused for Files (`mediaKind`).
- The capture screen fills the answer in through its own autosave (`applyProposals`): only modules the inspection includes, never the conclusion (the inspector's result, remark and signature), only fields still empty, only values each module's schema accepts, size by size, and field by field within a size the schema refuses whole (a refused aged sample no longer takes the size's boxes with it, 26 October 2026). Totals and results are still calculated by the app.
- **Sizes not on the order** (Kenneth, 27 October 2026: "why is the carton number not being auto filled?"): a reading fills a size's values whether the order lists the size or not, but a step shows only the sizes ordered (BUILD_SPEC 6.2 rule 4), so a spreadsheet read before the order had any sizes (size L's 50 box/carton numbers and 13 gloves' dimensions) seemed to fill nothing. The file's message now says so, in amber and for 12 seconds: "Steri-AI filled N fields from X. Size L is not on the order yet: add it on the Order page to see its values." (`applyProposals` names the sizes of the per-size steps it filled; `filledNotOrdered` in `lib/inspections/capture/not-ordered.ts` keeps those the order, the reading's own quantities counted, does not list). Each such step says it at its top too, with Open Order (docs/DESIGN.md, Components). Steri-AI never adds a size to the order: the order is the inspector's to confirm.
- **Aged sample** (Kenneth, 26 October 2026): a packing row marked as an aged sample ("Aged sample" in Others, usually no box/carton number) goes into that size's `agedSample` in `dispensing_packing`, never into its boxes (`PAPER_FORM_GUIDE`, and the field's own description in the data's JSON Schema, `moduleDataJsonSchema`); read as a ninth box it had left the whole packing check incomplete. It fills an empty aged sample like any field.
- **Box/Carton Numbers** (Kenneth, 14 October 2026: "if box and carton is the same thing, why the AI wont auto fill the carton number?"): each box/carton number a document gives for a size (the paper form's Dispensing Result, the labelling boxes, a list of the sampled cartons) also goes into that size's list of sampled cartons, in the document's order, each once and as written, but only while the list is empty (`PAPER_FORM_GUIDE`), and the screen lays it in as a list pasted into row 1 would go (`pasteCartons`: a repeat, or anything that is no box/carton number, left out; at most 2,000), never into a list that holds a number. The paper form lists only the boxes tested (13 of the 50 cases sampled on the example form), so the step stays Not Done until the rest are typed: a document listing every sampled carton fills the list only when it is read while the list is still empty, so before the form, never after it.
- **Weight** (Kenneth, 26 October 2026: "this page should only record average weight of each size, which already in the dimension document"): one value per size, the size's average weight as a document prints it, usually the dimension sheet's Weight (g) row or column, as that size's `values` (`WEIGHT_GUIDE`, and the description in weight's data schema). Its spec ("NA") and P/F ("Info only") are not data, and Steri-AI never averages glove weights itself: a document that lists each glove's weight without the average gives nothing for weight. The sampling plan's `glovesWeight` is never filled: the app has no such row.
- **Packing Configuration** (Kenneth, 27 October 2026: the gloves per case is worked out): a document that states the gloves per inner unit and the inner units per case fills those, and one that states the gloves per case fills it as read, only while it is empty; Steri-AI never works it out itself. A fill that leaves both counts entered and the gloves per case empty writes their product there, as typing them does (`withWorkedOutGlovesPerCase`), not counted among the fields filled. A stated one that is not the product keeps calc's warning.
- The reading is kept on the file row (`ai_status` `read` or `failed`, `ai_read_at`, `ai_summary`; migration `20261009150000`), so a file is read once whichever device uploaded it. Each file row is one line: the name with a **Steri-AI Verified** badge beside it (its tooltip: what the document is), then Preview (a dialog on the page: PDFs in the browser's viewer, photos as images, spreadsheets as tables), Download and Delete as icons; the step's tick turns green once every file is verified. A file the AI could not read shows **Not Read** (the reason as its tooltip) and Read Again. Not connected or a model error leaves the file unread, to be read once the AI works.
- **The proposals are kept until they are filled in** (Kenneth, 26 October 2026: "why is the sampling plan not filled by AI?"). A reading takes some ten seconds, and it used to answer only the screen that started it: he had opened Steri-AI Settings meanwhile, so the sampling plan read from his photo was never filled in, and the file, read, was never read again. Now `readSourceFile` keeps the proposals with the file (`ai_proposals`, and `ai_filled_at` null; migration `20261026120000`). The screen that started the reading fills them in at once and records it (`markSourceFilled`, which sets `ai_filled_at`); a screen that is gone by then fills nothing. The next capture screen to open the inspection, on any device, finds the proposals no screen has filled in (`getSourceDocumentStatuses`, `sourceFileStatus`), fills them into the empty fields the same way, with the same "Steri-AI filled N fields from X." message, and records it, so they go in once and a field cleared later is not filled again. A file read before 26 October has no proposals kept. **Read Again** now sits beside Steri-AI Verified too: it reads the file once more, keeps the new proposals and fills the fields still empty. Only the app writes these columns, with the secret key: the database refuses `ai_status`, `ai_read_at`, `ai_summary`, `ai_proposals` and `ai_filled_at` from a signed-in user's own request (`reading_guard`).
- The audit log records `source_document_read` (file, modules proposed, where the file was linked, who, model). Inspection data goes to Anthropic as in "Data handling" below.

**Files / Media** (Kenneth, 11 October 2026): a toggle in the card's header. Files holds the forms and PO papers the AI reads. Media holds the inspection's photos and videos, taken on the inspector's phone during the visit: photos go through the photo queue as before (2048 px JPEG), untagged (`module_key` null; tag them in the gallery when the report needs a photo in a section), and the tab lists every photo of the inspection; videos (MP4, an iPhone's QuickTime movie, WebM, up to the file bucket's 50 MB) are `inspection_files` with `module_key` `source_media` (migration `20261011180000`), previewed in the same dialog. The AI reads Media only to file it (Auto-Sort, below). The steps no longer have a photo box under them; the inspector comment stays.

## Auto-Sort (Media)

Media's photos and videos sit in four categories (`MEDIA_CATEGORIES`, Kenneth, 11 October 2026): Warehouse, Product and Package Samples, Inspection Proof (the inspection under way, as proof it was done) and Product Defects, with Other for the rest. Auto-Sort (Kenneth, 12 October 2026) files them for the inspector: they drop every photo and video from the visit at once (on Media, or on New Inspection's card, whose run starts once the inspection exists), each uploads into Other, the screen makes a small JPEG preview (at most 1024 px on its long edge; a frame for a video) and sends up to 12 at a time to the Server Action `sortMediaWithAi` (`app/(app)/inspections/[id]/media-actions.ts`). Claude (`lib/ai/media-sorter.ts`: the Reading Documents model, low effort, one request per batch) sees each preview after a label ("Item 2 (video frame)") and answers a category for each, or unsure.

- What Claude is sure of is filed at once, with the same write as a move by hand: the photo's or video's `module_key` takes the category's key, and a photo's old target goes (categories record no size, hand or defect, as in the tag picker). **Unsure items stay in Other** for the inspector to file by hand.
- Any item can then be dragged to another category or back to Other (Server Action `moveMedia`; Other is no tag for a photo, `source_media` for a video).
- **Filing only.** Auto-Sort sees the previews and nothing else: it never reads the inspection's data, never fills a field and never changes a result.
- Who may: the rule for retagging a photo, the database's `can_edit_inspection` (the inspector while it is a draft or reopened, admins until it is approved), checked before Claude is asked; each item must be one of the inspection's photos, or a video on its Media (never a Source Document or a step's lab report). The previews are not stored.
- The audit log records `media_moved` for each move by hand (the photo or file id, the `from` and `to` tags, a photo's old target, `by`) and one `media_sorted` per batch (`photos` and `videos` sent, how many went into each category, how many were `unsure`, `not_saved` when a write failed, the `model`, `by`). The service role writes both, as it does `source_document_read`, so the history names the system and `by` the user.
- Not connected, nothing moves and the screen says "Auto-Sort needs Steri-AI, which is not connected yet. Ask an admin to add the Anthropic API key under Admin > Steri-AI Settings." A failed request comes back in words the inspector can act on (busy, too slow, could not reach the AI).
- The previews go to Anthropic as in "Data handling" below.

**Lab reports and certificates** (Kenneth, 12 October 2026: "Lab report should be automatically detected by AI and fill in"): files are uploaded here only, and Steri-AI links them; a step has no picker. Each reading is told where this inspection files a document itself, in the template's words (`attachTargets` in `lib/ai/source-reader.ts`: tensile's and force at break's lab report by the module's title, each row on the documents checklist by its label), and answers `attachTo` when the file itself is a lab report with tensile or force at break results (`tensile`, `force_at_break`) or a documents row's certificate or report (`documents.<item>`). It reads the report's results into those steps too, as any document's values (`LAB_REPORT_GUIDE` in `lib/ai/reading-guide.ts`: tensile's averages per size, before ageing; force at break's reading of each glove, in order). `readSourceFile` then keeps the file's id there through the reading's proposals (`linkSourceFile`: included modules and rows on the checklist, never an id the AI wrote itself): a documents row's `file` only where nothing is linked yet, never over an earlier link; a lab report added to the step's `labReports`, once per file, with the sizes the reading gave that step values for, never in place of another report (one report per size is common; a report read again gains the sizes it lacked), sets the file's `kind` (`lab_report` or `certificate`) and records `linked` in the audit details; the capture screen fills the link in with the other proposals, so the step shows it without a reload.

- **Tensile and force at break** show their lab reports in one line (the framework's `LabReports`, a `source-file-link.tsx` slot per report inside the kit's `AttachmentStatus`): each report in size order as "Size S · <file name>" (the name alone when its sizes are not known), a sparkle when Steri-AI linked a Source Document, Preview and Unlink (which never deletes the file and leaves the other reports), under "Lab Reports" when there are several. Nothing linked: "Steri-AI is reading the Source Documents…" while one of them is unread or being read (`useSourceDocuments` shares its readings with the steps), else "No lab report detected by Steri-AI.". A lab report uploaded on a step before 12 October still counts and shows the same, without Unlink; a kept file that is gone keeps calc's warning, named by its sizes, with Unlink.
- **One lab report per size** (Kenneth, 26 October 2026: "this is inaccurate, there are 4 different source"). INS-2026-2437's force at break showed one report where the lab had issued four, one each for S, M, L and XL: a step kept one `labReport`, filled only while empty, so the first report read took it, the second's fill was dropped and the last two were never linked. Each step now keeps a list, `labReports: [{ fileId, sizes }]`, and every report Steri-AI files joins it: the prompt says to file every lab report, also beside one a step already lists, and to give a lab report's results for every size it reports even where they are entered (an exception to leaving out what the current data holds, as for box/carton lists; the fill still keeps what is entered), so each report is linked with its sizes. Data saved with one `labReport` reads as a list of it with no sizes; Read Again on such a report gives it its sizes. Tensile needs at least one attached; the export's module data names every report by `fileId` with its `sizes`.
- **Documents**: a row whose document Steri-AI linked shows the file on its attachment line (name, Preview, Unlink); while no row has one, one line under the list says "No documents detected by Steri-AI." (or that Steri-AI is still reading).
- Read-only, the same without Unlink. If Steri-AI misses a lab report, nothing can be linked by hand: the inspector uploads a clearer copy.

## Steri-AI Summary

The **Steri-AI Summary** button beside the Conclusion's Inspection Summary field (Kenneth, 12 October 2026) drafts the summary from the inspection in SteriCare's house style. Steri-AI writes text only: it reads the conclusion and never writes it, so no result, remark, date or signature changes, and nothing enters the inspection until the inspector's screen inserts the draft through the editor and autosave, where `saveCaptureData` checks it against `ConclusionDataSchema` again. Once inserted it is the inspector's text: edited, saved, exported, reviewed and signed like typed text. Two things only record that Steri-AI drafted it: a "Drafted by Steri-AI" mark under the field, on that device, until the text is edited (never in the report, the export or the review), and the audit log.

## The paper form and shortforms

**One PO per inspection** (Kenneth, 11 October 2026, after speaking to the inspector): each inspection is one purchase order, and the forms of other POs are uploaded to their own inspections. ### Verifying the signature

Verify the raw body before parsing it, reject timestamps more than 5 minutes from your clock, and compare in constant time. A Node or Next.js receiver:

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

const TOLERANCE_SECONDS = 5 * 60;

export function isSignedBySteriCare(
  rawBody: string,
  timestamp: string | null,
  signature: string | null,
  secret: string,
  nowSeconds = Math.floor(Date.now() / 1000),
): boolean {
  if (!timestamp || !signature || !/^\d+$/.test(timestamp)) return false;
  if (Math.abs(nowSeconds - Number(timestamp)) > TOLERANCE_SECONDS) return false;
  const match = /^sha256=([0-9a-f]{64})$/i.exec(signature);
  if (!match) return false;
  const expected = createHmac("sha256", secret).update(`${timestamp}.${rawBody}`).digest();
  return timingSafeEqual(expected, Buffer.from(match[1], "hex"));
}

export async function POST(request: Request): Promise<Response> {
  const rawBody = await request.text();
  const secret = process.env.AI_WEBHOOK_SECRET ?? "";
  const valid = isSignedBySteriCare(
    rawBody,
    request.headers.get("X-SteriCare-Timestamp"),
    request.headers.get("X-SteriCare-Signature"),
    secret,
  );
  if (!secret || !valid) return new Response("Invalid signature", { status: 401 });

  const exportDoc = JSON.parse(rawBody);
  // ... write the report or the review from exportDoc ...
  return Response.json({ reportUrl: "https://reports.example.com/INS-2026-0001.pdf" });
}
```

Test vector: secret `whsec_test_0123456789abcdef`, timestamp `1720000000`, body `{"refNo":"INS-2024-0001"}` gives `sha256=5157e5af21b53cbd68da3b5566c0cf2eb0c3214c8a86d3493feb6821b1fc2335`. Check from a shell:

```sh
printf '%s' '1720000000.{"refNo":"INS-2024-0001"}' | openssl dgst -sha256 -hmac 'whsec_test_0123456789abcdef'
```

The app's own helper is `verifySignature()` in `lib/ai/webhook.ts`.

## The second opinion on Claude

What `lib/ai/providers/claude.ts` sends, in one streamed request (`client.beta.messages.stream`):

- **System prompt** (`lib/ai/prompts/review-system.ts`): a senior glove QC auditor (ISO 2859-1 with AQL, EN 455, ASTM D6319, this app's modules) giving a second opinion. It lists what to check (weight deviation, duplicate or out-of-range box/carton numbers, critical defects, results that do not follow from the data, sizes not ordered, totals, dates), how to calibrate confidence and how to grade severity. Since 12 October 2026 it describes weight as weighing the sampling plan's # Gloves for Weight (the template's n, 13 on STD_EG, when the plan gives none; one value per size on SAFEDON_EG), never the dimension sample. Since 13 October 2026 (Kenneth: box # and carton # are one number, "yes link again") it describes the boxes of dispensing and labelling as the size's sampled box/carton numbers: one the size's list does not hold is the app's warning (`box_not_in_carton_list`), never an error and often a slip (one digit off a sampled number, say), and the same number in several dispensing rows is no problem. It is byte-stable and sent with `cache_control`, so repeat reviews within 5 minutes read it from the cache.
- **User turn**: the export inside `<inspection_export>` tags, then up to `AI_REVIEW_MAX_PHOTOS` photos as image URLs (include-in-report photos first; flagged photos are skipped because the API cannot read them), each labelled with its photo id. Signed URLs are removed from the JSON text, and so is the inspector's email; the Inspection Summary goes as its plain text only, which the reviewer reads as the inspector's text and checks against the data and the final result.
- **Depth**: thinking is always on for Claude Opus 5.5; `output_config.effort` is set from `AI_REVIEW_EFFORT` (the API default would be `medium`). No `temperature`, `thinking` or prefill: this model rejects them. `max_tokens` covers thinking plus the answer: 16,000 at `low`, `medium` and `high`, and 64,000 at `xhigh` and `max`, which think longer (Anthropic advises at least 64K at those levels). An answer that still runs out of room comes back as a cut-off answer.
- **Structured output**: `output_config.format` carries a JSON schema generated from `AiReviewSchema`. Structured outputs are generally available, so they need no beta header. The SDK's `zodOutputFormat` is not used: in SDK 0.131 its transform turns `enum` into description text (so `pass | fail | hold` would not be enforced), and its parser throws on a cut-off answer, which fails the stream before `stop_reason` can be read. `lib/ai/providers/claude-format.ts` keeps the enums and leaves parsing to the provider, which checks `stop_reason` first and then validates the last text block with zod. When a fallback model takes over mid-stream, the declined model's partial text comes before the fallback model's answer.
- **Refusal fallbacks are enabled**: `fallbacks: "default"` with the beta header `server-side-fallback-2026-07-01`. If Claude Opus 5.5's safety classifiers decline the request, the API reruns it on the fallback model Anthropic recommends for that category, in the same call. The `model` stored with the review is the one that wrote it. Only when the whole chain declines does the outcome become `refused`.
- **Streaming and the time limit**: the answer streams in as Claude writes it. A non-streaming call that thinks for minutes risks HTTP timeouts, and anything above about 16,000 output tokens has to stream. One time limit covers the whole review, retries included: 10 minutes at `low` to `high`, and 30 minutes at `xhigh` and `max` (the SDK's own estimate for that many output tokens). `requestAiReview(exportDoc, { timeoutMs })` overrides it.
- **Retries**: the SDK's own retries are off, because the SDK would rerun a timed-out review from the start and it would be billed twice. The provider retries only failures that come back before Claude writes anything: rate limits (429), overloads (529) and other 5xx answers, and connections that never opened. It retries at most twice, honouring `retry-after` (otherwise it waits 1 second, then 2). A wait of more than a minute, or one that would pass the time limit, is reported instead. A timeout, or an error after the stream opened, is never retried; the admin can run the review again. If a request with photos is rejected as invalid (for example an expired photo link), it is sent once more without photos.

Other models: the request shape targets Claude Opus 5.x. Effort, structured outputs and `fallbacks` are not supported by every model; an unsupported combination comes back as `error` with the API's explanation.

## Steri-AI Cost

Steri-AI Settings > Steri-AI Cost (`/admin/ai?view=cost`) shows what Steri-AI costs: an estimate from the tokens Anthropic reports for each call, priced with the list in force when the call was made. Anthropic's bill, in US dollars, is final. The view shows ringgit by default, or US dollars, by its RM | USD switch (Kenneth, 13 October 2026: "give me currency toggle i can toggle on my own").

**What is recorded.** Every Claude call the app makes is one `ai_usage` row (migration `20261013120000`, docs/DATABASE.md), written with the secret key by `recordAiUsage` (`lib/ai/usage.ts`) after the response is sent, so recording never slows or fails the user's action. The readers report through `createMessage` and the second opinion from `reviewWithClaude` (`onCall`):

| Job (`feature`) | One row per | Inspection |
|---|---|---|
| New Inspection (`new_inspection_read`) | document read | none: it does not exist before Create |
| Source Documents (`source_document_read`) | file read and filled in | the inspection |
| Auto-Sort (`media_sort`) | batch of up to 12 previews (`item_count`) | the inspection |
| Second Opinion (`second_opinion`) | review, from the admin's button or on submit | the inspection |
| Inspection Summary (`inspection_summary`) | Steri-AI Summary call: a draft (`item_count` 1) or its check retry (0), Try It's included | the inspection |

Each row keeps the model that answered, who asked (the admin, or the user who submitted), the tokens (uncached input, output with its thinking, 5-minute and 1-hour cache writes, cache reads), how long it took, the outcome (`ok`; `refused` and `cut_off`, billed but not usable; `failed`, no answer, with the error type) and `cost_usd`. A server-side fallback bills each attempt at its own model, and the top-level usage covers only the last one, so the tokens come from `usage.iterations`, summed. A failed call costs 0: no answer came back, so there are no tokens to price (refused and cut-off answers are billed, and counted). Deleting the inspection or the person clears the link and keeps the row. Not recorded: Test Connection (no tokens), the AI report and review webhooks and the mock reviewer (no Claude call from the app), and requests that never reach Claude (no key, a file too large or of a type the readers do not take). Counting starts with migration `20261013120000`: earlier calls kept no tokens, so they are not estimated.

**The formula** (`costOfCall`): for each attempt, uncached input, 5-minute cache writes, 1-hour cache writes, cache reads and output, each times its rate for that model, per million tokens. A dated snapshot (`claude-opus-5-5-20260922`) takes its model's prices. Claude Haiku 5.5's higher rates apply to a whole request whose prompt (input, cache writes and reads) is over 100,000 tokens, output included. Then x1.1 when `usage.inference_geo` is `us` (US-only inference, also from a workspace default) and x0.5 for the Batch API (not used). Six decimals. The refusal fallbacks have built-in prices (`FALLBACK_MODEL_PRICES`): the review's (Claude Opus 5 and Opus 4.8, 5 / 25 USD) and the Steri-AI Summary's (Claude Sonnet 5.5 falls back to Sonnet 5, 2 / 10 USD), so a turn one of them serves is priced; an admin's own entry for them wins. A call on any other model without a price stores no cost and counts as No Price; adding its price prices later calls only. Prompt caching counts at its own rates: the first Source Document of an inspection writes the cached modules block, and files read within 5 minutes read it at 0.20 USD per million tokens on Opus 5.5 instead of 4; the review's system prompt is cached the same way. Example: Opus 5.5 with 20,000 input, 3,000 cache-read and 4,000 output tokens is 0.08 + 0.0006 + 0.08 = 0.1606 USD.

**The prices** (`DEFAULT_AI_PRICES`, `lib/schemas/ai-prices.ts`), USD per million tokens, read on 12 October 2026 from https://platform.claude.com/docs/en/about-claude/pricing and checked against each model's page and https://claude.com/pricing (standard inference):

| Model | Input | Output | Cache Write (5 Min) | Cache Write (1 Hour) | Cache Read |
|---|---|---|---|---|---|
| Claude Opus 5.5 | 4 | 20 | 5 | 8 | 0.20 |
| Claude Sonnet 5.5 | 2 | 10 | 2.50 | 4 | 0.10 |
| Claude Haiku 5.5 | 0.10 | 0.50 | 0.125 | 0.20 | 0.01 |
| Claude Haiku 5.5, prompt over 100,000 tokens | 0.50 | 2.50 | 0.625 | 1 | 0.05 |

Admins edit the list in the view (`ai_settings.prices`, null for the app's list; `saveAiPrices`): the day they checked it, an added model, and optionally their own ringgit rate with its date (Use My Own Rate, RM per US$1, from 1 to 20 so a typo such as 40.86 is refused; the schema keeps up to 100 so a saved list always reads), used instead of Bank Negara Malaysia's. The app's three models always stay in it (`withDefaultModels`). A change prices later calls only: each row keeps the cost it was recorded with. There is no pricing API, so the list is checked by hand. Saving any change stores the whole list, so later changes to `DEFAULT_AI_PRICES` reach the project only for models it lacks: Use Default Prices brings them back.

**Ringgit.** Costs are recorded and summed in US dollars (`cost_usd`), as Anthropic bills, before tax; the view converts them as it shows them (`_components/money.ts`: "RM 0.09", small amounts to the figures that matter, as for dollars), so nothing is stored in ringgit and the ringgit figures move with the rate. The rate (`lib/ai/myr-rate.ts`, `pickMyrRate`): the admin's own when the price list has one; else Bank Negara Malaysia's USD middle rate at noon (the 12:00 interbank session; RM per US$1, 4 decimals) for the latest business day it has published; else the last one read since the server started; else the built-in rate, RM 4.0860 for 13 October 2026, and the view then says Bank Negara Malaysia could not be reached. The server reads BNM's Open API (`https://api.bnm.gov.my/public/exchange-rate/USD/year/{y}/month/{m}?session=1200` with `Accept: application/vnd.BNM.API.v1+json`, free and without a key; the browser cannot, for want of CORS) and keeps the answer a day in Next's fetch cache. The month route has the day's noon rate from the early afternoon (13 October's appeared at 13:46), so before then, and for up to a day after while Next keeps the answer, the rate is the previous business day's; early in a month, when this month has none yet (BNM answers with no rows, `{"data":[]}`), the previous month's last. A rate outside RM 1 to 20 per US$1 is taken for a misread and skipped. BNM gets 2.5 seconds; after a failure it is left alone for 15 minutes, so the page never waits on it twice in a row. In ringgit, the filter row's note is one line naming the rate: "US$1 = RM 4.0823 · 12 Oct 2026 · Source: Bank Negara Malaysia", linking BNM's terms for its data (https://www.bnm.gov.my/terms-of-use-bnm-datasets: free to use with that source line), or "· set in the price list"; with the built-in rate, "built-in rate" before the source. The "i" before it opens what the figures are (Kenneth, 13 October 2026: the note was too crowded): estimated from token use, Anthropic's bill in US dollars final, ringgit figures moving with the exchange rate, when counting started, and, with the built-in rate, that Bank Negara Malaysia could not be reached (`costNoteDetails`). The switch replaces the address like the period, and each admin's last choice is kept on the device (`_components/cost-currency.ts`, localStorage per user): the view switch opens Steri-AI Cost on it, and so does an address without a currency once the page has loaded (dimmed while it changes). The Price List stays in US dollars per million tokens, as Anthropic lists them, with each price's ringgit beside it while ringgit shows. Try It on the Inspection Summary card says what a try costs in the same remembered currency ("about RM 0.08 to RM 0.20").

**The view's numbers** (`loadAiCostReport`, `lib/ai/cost-report.ts`, read with the admin's own client: the functions `ai_usage_summary`, `ai_usage_trend` and `ai_usage_by_inspection` give anyone else no rows): the last 7, 30 or 90 Malaysia days or All Time; cost per job and per model, per document, per photo or video sorted and per review; per inspection, where New Inspection reads and drafts deleted since are counted apart; and a monthly rate once 7 days are counted. Days before the first recorded call are not drawn as zero cost.

**On screen**, top to bottom (`_components/cost-*.tsx`): the Period (Last 7, 30 or 90 Days, All Time) and the Currency switch (RM | USD), with the note: in ringgit the rate line, in dollars "Estimated from token use", each after an "i" that holds what the figures are and when counting started; three tiles (Total Cost with its calls, failures and calls with no price; Per Inspection; Per Month at this rate); Cost per Day (by month for All Time over 92 days), a CSS column chart whose readout names the highest day, or the day a pointer, a tap or the arrow keys pick, with that day's jobs; Cost by Job, with what one document, photo or video, or review costs, and Cost by Model, with a line where calls had no price; Cost by Inspection, the 50 costliest, each linked to its review or capture screen, with New Inspection reads and deleted drafts under it; and the Price List. Filters replace the address, so Back leaves the view rather than each filter. Before the first call: No Steri-AI Costs Yet, the price list still below, in dollars alone (ringgit shows only with the switch and its rate line).

**Limits.** An estimate, not the invoice. A request that timed out or broke off mid-stream, and the SDK's own retry of one (the readers allow one), may be billed and not seen, so the estimate can run low; a fallback's declined attempt is counted with the tokens Anthropic reports, although a decline before any output is billed only in some categories. Days are Malaysia days and Anthropic's Console counts UTC days, so one day can differ. Matching the invoice automatically needs the Usage & Cost Admin API: an organisation account and an Admin API key, which can manage members and keys and so never goes in the app. That is not built: compare with Console > Usage and Cost by hand.

**A second opinion's size.** A review reads the system prompt (about 2,300 tokens), the export (about 4,000 tokens for one size, more for several) and the photos (up to about 4,800 tokens each at 2,048 px), then writes thinking plus the answer: about 0.15 to 0.50 USD at `high` effort with six photos on Opus 5.5. At `xhigh` and `max` the output budget is 64,000 tokens, up to about 1.30 USD on output alone. Lower the effort or the photos per review to spend less.

## Data handling

- Inspection data goes to whichever provider is configured: the full export (with 24-hour signed photo and file links) to a webhook, or the export without links plus the selected photos to Anthropic. Exports carry client, manufacturer, PO, lot and carton details and inspector names.
- Reading documents (New Inspection, Source Documents) sends the file to Anthropic (an Excel or CSV file as its text, every sheet, hidden ones included), and Auto-Sort sends small previews of Media's photos and video frames; labels and cartons in them can show the same details.
- The Steri-AI Summary sends Anthropic a compact view of the inspection (client, manufacturer, PO and lot details when recorded, results, comments, the remark and photo captions; no links or files), the inspector's note or own text when given, and the admin's example summaries with every request, for every client: their hint asks for placeholders.
- Before using Claude in production, check Anthropic's commercial terms and data-retention options (zero data retention is arranged per organization) against SteriCare's agreements with its clients. For a webhook, the same questions apply to whoever runs it.
- Keep `ANTHROPIC_API_KEY` and `AI_WEBHOOK_SECRET` server-side only: never prefix them with `NEXT_PUBLIC_`. `lib/ai` imports `server-only`, so the build fails if client code imports it.
- Test fixtures replace client, manufacturer, PO, lot and carton identifiers with placeholders (BUILD_SPEC rule 7).

## In the app (Phase 3)

The hand-offs are wired into the app; this is where each part lives.

- **The export**: `GET /api/inspections/[id]/export` (`app/api/inspections/[id]/export/route.ts`) answers the inspection's inspector and admins (401 signed out, 403 inactive, 404 for anyone else) with `buildInspectionExport` (`lib/export`): the inspection run through the module framework as capture and submit run it, its files passed to the context (`InspectionMeta.files`, so a deleted lab report reads as missing), validated by `ExportSchema`. Photos, files, the client logo and the template's source file get 24-hour signed URLs. Lab reports and certificates are referenced by id in module data (`force_at_break` and `tensile` `labReports[].fileId`, each with the sizes it gives results for; `documents` `items.<item>.file`), so a receiver matches them with `files[].id`. Each module also carries its `config` as the template version sets it.
- **The review screen** (`/inspections/[id]/review`) shows the AI panel between the result and the module results: `LoadedAiReviewPanel` from `components/ai`, loaded beside the review by `loadAiPanel` (`lib/inspections/ai`). Elsewhere, `<AiReviewPanel inspectionId={id} />` loads itself. It puts the system's computed results, the inspector's result, remark and comments, and the AI's opinion side by side, per module; admins request second opinions, record agree, disagree (a note is required) or fixed per finding (`ai_review_actions` and the audit log), and send to the AI report; the inspector reads the opinions. Not connected, the panel says so, and tells admins whether `AI_REVIEW_PROVIDER` is `off` or nothing is set up. When the inspection's results cannot be worked out (its template version or saved data cannot be read), `loadAiPanel` answers `unreadable` and the panel says quietly that the second opinion and the AI report are not available, since the review's checks already give the cause; only a read that failed shows as an error.
- **Server Actions** (`lib/inspections/ai/actions.ts`): `requestAiSecondOpinion`, `recordAiFindingDecision`, `sendToAiReport` (stores `report_url`; when not connected it offers the JSON download) and `getAiReviewProgress` for the panel's poller.
- **The second opinion** runs from the admin button or on submit. `startAiReview` stores a `pending` `ai_reviews` row, then writes the opinion in `after()`, `done` or `failed`. `scheduleAiReviewOnSubmit(inspectionId)` is the submit trigger: the submit action calls it after the status change when the template's `ai.reviewOnSubmit` is on; it runs as the service role, never throws, and does nothing when no reviewer is connected.
- **Time limit**: a Claude review can take 10 minutes (30 at `xhigh` and `max`), and it runs inside the Server Action's `after()`, so the page that runs the action sets `export const maxDuration` above that. The review page sets 800 seconds, the most Vercel allows on Pro; the capture page needs the same for the submit trigger. Keep `AI_REVIEW_EFFORT` at `high` or below there, or pass a shorter `timeoutMs`.
- **Versions**: a review is kept per version of the inspection's content. `ai_reviews.inspection_fingerprint` (migration `20261007113245`) is a SHA-256 of the data, module overrides, final result, remark, template version and files (`inspectionFingerprint` in `lib/inspections/ai/fingerprint.ts`); approving, reopening or storing the report link changes none of them, so the opinion stays current. Photos are left out: they decide no result. A review stored without a fingerprint compares by `inspection_updated_at`, the save it reviewed. One review per version may be pending at a time (`ai_reviews_one_pending_per_content`, and `ai_reviews_one_pending_per_version` for reviews without a fingerprint): a second request answers "A second opinion of this version is being written."
